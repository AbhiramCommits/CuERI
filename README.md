# cuERI

cuERI is a small, library-style implementation of the Gaussian-basis integral
primitives that every Hartree–Fock or density-functional quantum-chemistry code
is built on.  Given a molecule (atomic numbers and Cartesian coordinates) and a
contracted Gaussian basis of s, p and d shells, it computes the overlap matrix
`S`, the kinetic-energy matrix `T`, the nuclear-attraction matrix `V` and the
full two-electron repulsion tensor `(μν|λσ)`.  The integrals are evaluated by
McMurchie–Davidson Hermite recurrences, with an independent Rys-quadrature path
for cross-checking, Schwarz shell-pair screening to skip negligible quartets,
and angular-momentum batching.  A public C99 API, a Python `ctypes` layer and a
CMake package make it usable as a component rather than as a monolithic program.

For a chemist, the library turns "the basis set and the geometry" into the
matrices that the SCF equations need, with the same conventions as PySCF/libcint
(up to the documented normalization reconciliation).  For an engineer, it is a
single `CUEST_HD` header set compiled twice — once for the CPU with OpenMP and
once for CUDA — with a flat C ABI, explicit status codes, fp32/fp64 precisions
and measured accuracy and throughput.  The repository also contains the
validation harness: a NumPy RHF closed loop that uses only cuERI integrals and
reproduces PySCF's total energy for water to about 1e-11 Hartree.

## The physics and the mathematics

### McMurchie–Davidson Hermite expansion

The product of two Cartesian Gaussians centred at **A** and **B** is a Gaussian
centred at the product centre **P** = (a**A** + b**B**)/(a+b), multiplied by a
polynomial.  McMurchie and Davidson expand that polynomial in Hermite
Gaussians,

```
exp(-a|r-A|²) exp(-b|r-B|²)
    = K exp(-μ|A-B|²) Σ_t E_t^{ij} Λ_t(r-P),
Λ_t(r-P) = (∂/∂P)^t exp(-p|r-P|²),   p = a+b,  μ = ab/p,
```

with the coefficients generated by the one-dimensional recurrence

```
E(i+1,j,t) = E(i,j,t-1)/(2p) + (P_x-A_x) E(i,j,t) + (t+1) E(i,j,t+1)
E(i,j+1,t) = E(i,j,t-1)/(2p) + (P_x-B_x) E(i,j,t) + (t+1) E(i,j,t+1)
E(0,0,0)   = K.
```

The overlap is then `E_0 (π/p)^{3/2}`; the kinetic energy uses the symmetric
gradient form `T = ½∫∇φ_a·∇φ_b`, which expands into overlap-like terms with
raised and lowered angular momenta; and the nuclear attraction uses the Hermite
Coulomb auxiliary described next.

### The Hermite Coulomb auxiliary

The nuclear-attraction integral needs

```
R_{tuv}(n) = ∫ Λ_{tuv}(r-P) / |r-C| dr,
```

which obeys

```
R_{t+1,u,v}(n) = t R_{t-1,u,v}(n+1) + (P_x-C_x) R_{t,u,v}(n+1),
R_{0,0,0}(n)   = (-2p)^n F_n(p |P-C|²),
```

where `F_n` is the Boys function.  The same auxiliary, evaluated with the
effective exponent `α = pq/(p+q)` and the centre difference `P-Q`, gives the
two-electron integrals:

```
(ab|cd) = 2π^{5/2}/(p q √(p+q)) Σ_{t,u} E_t^{ab} E_u^{cd} (-1)^{|u|} R_{t+u}(α, P-Q).
```

The sign follows from `J_{tu} = ∂_P^t ∂_Q^u J_00` with `∂_Q = -∂_P`.  The whole
recurrence is generated downward in `n`, so only `F_0 ... F_8` are ever needed.

### Rys quadrature

The same sum can be written as a one-dimensional integral over `t ∈ [0,1]`,

```
(ab|cd) = C ∫_0^1 exp(-T t²) Π_d P_d(t²) dt,
```

whose moments are exactly the Boys values `F_k(T)`.  cuERI builds the
corresponding Gauss rule from those moments at run time
(Gram–Schmidt/Stieltjes followed by a Jacobi diagonalisation of the resulting
tridiagonal matrix), so no root tables are committed and the fp32 and fp64
paths use the same rule.  For l ≤ 2 the rule needs at most five roots.  The
weight is scaled with `S = max(T,1)` before the orthogonalisation; without that
scaling the moment Hankel system is catastrophically ill-conditioned for large
`T`.

### The Boys function, and why naive recursion is unsafe

`F_n(T) = ∫_0^1 t^{2n} e^{-Tt²} dt` is evaluated in three branches: a Taylor
series for `T < 1e-8`, downward recursion seeded by an accurate `F_N` for
`1e-8 ≤ T < 30`, and `F_0 = √(π/(4T)) erf(√T)` followed by upward recursion for
`T ≥ 30`.  The middle branch matters.  The upward recurrence

```
F_{n+1} = ((2n+1) F_n - e^{-T}) / (2T)
```

divides by `2T`; for small `T` the subtraction cancels catastrophically and the
error is amplified by roughly `(1/(2T))^n`, which destroys the n = 8 values that
d-shell quartets need.  Downward recursion (`F_n = (2T F_{n+1} + e^{-T})/(2n+1)`)
is contractive instead, and its seed is computed from the positive-term
incomplete-gamma series, which has no cancellation.  The measured worst relative
error of the implementation over `T = 1e-16 … 1e3`, `n = 0…12` is
4.94e-14 at `T = 8.06e-15`, `n = 10`.

## Architecture

```
  C caller                     Python caller
      |                             |
      v                             v
  include/cuest/cuest_eri.h    python/cuest/__init__.py (ctypes)
      |                             |
      +-------------+---------------+
                    v
             src/cuest_api.cpp            opaque handles, status codes,
                    |                     precision/algo validation
                    v
          +---------+----------+
          |                    |
   src/one_electron.cpp    src/eri_cpu.cpp        host dispatch
   shell-pair loop         shell pairs -> Schwarz -> canonical quartets
          |                    |                    -> AM batches
          +---------+----------+
                    v
   src/kernels/{boys,shell,md_recurrence,eri_md,eri_rys}.cuh
   (one copy, CUEST_HD = __host__ __device__ under nvcc)
                    |
          +---------+----------+
          |                    |
    CPU backend           CUDA backend
    OpenMP over pairs     src/cuda/cuest_kernels.cu
    fp32/fp64 templates   templated <T,LA,LB,LC,LD>, SoA device basis,
                          event timing -> cuestEriStats_t.kernel_ms
```

Screening and batching pipeline:

```
shells -> unordered shell pairs (i>=j) -> Q_pq = sqrt(max |(pq|pq)|)
       -> canonical quartets (i>=j, k>=l, pair(i,j)>=pair(k,l))
       -> drop quartets with Q_pq Q_rs < tol
       -> group by (L_i+L_j, L_k+L_l) class
       -> per-quartet kernel -> scatter the 8 permutations into the tensor
```

File map:


## Public API

Every function returns `cuestStatus_t`; no exception crosses the C boundary.
The full reference is the Doxygen in `include/cuest/cuest_eri.h`.

| function | purpose |
|---|---|
| `cuestCreate`, `cuestDestroy` | handle lifecycle |
| `cuestGetBackend` | which backend the handle selected (CPU or CUDA) |
| `cuestSetEriAlgo` | select `CUEST_ERI_ALGO_MD` or `CUEST_ERI_ALGO_RYS` |
| `cuestGetVersion`, `cuestGetErrorString` | version and status text |
| `cuestBasisCreateFromFile`, `cuestBasisDestroy` | load molecule + basis from JSON |
| `cuestBasisNumFunctions`, `cuestBasisNumShells`, `cuestBasisShellInfo` | basis introspection |
| `cuestOverlapMatrix`, `cuestKineticMatrix`, `cuestNuclearMatrix` | one-electron matrices |
| `cuestSchwarzBounds` | `Q_pq` shell-pair bounds |
| `cuestERIBatch` | caller-selected quartets, packed or offset blocks |
| `cuestERITensor` | full `nbf⁴` tensor with 8-fold symmetry and statistics |

Compilable usage (`examples/water_fock.c`, abbreviated):

```c
#include <stdio.h>
#include <stdlib.h>
#include <cuest/cuest_eri.h>

int main(void) {
  cuestHandle_t handle = NULL;
  cuestBasis_t basis = NULL;
  cuestCreate(&handle);
  cuestBasisCreateFromFile(handle, "data/molecules/h2o.json", "sto-3g", &basis);

  int nbf = 0;
  cuestBasisNumFunctions(basis, &nbf);
  double *S = calloc((size_t)nbf * nbf, sizeof(double));
  double *T = calloc((size_t)nbf * nbf, sizeof(double));
  double *V = calloc((size_t)nbf * nbf, sizeof(double));
  double *eri = calloc((size_t)nbf * nbf * nbf * nbf, sizeof(double));
  cuestEriStats_t stats;

  cuestOverlapMatrix(handle, basis, CUEST_FP64, S, nbf);
  cuestKineticMatrix(handle, basis, CUEST_FP64, T, nbf);
  cuestNuclearMatrix(handle, basis, CUEST_FP64, V, nbf);
  cuestERITensor(handle, basis, CUEST_FP64, 1e-10, eri, &stats);

  double trace = 0.0;
  for (int i = 0; i < nbf; ++i) trace += T[i * nbf + i] + V[i * nbf + i];
  printf("core Hamiltonian trace: %.12f Hartree\n", trace);
  printf("screened %zu of %zu quartets\n", stats.quartets_screened, stats.quartets_total);

  free(eri); free(V); free(T); free(S);
  cuestBasisDestroy(basis);
  cuestDestroy(handle);
  return 0;
}
```

Running it prints `core Hamiltonian trace: -74.824447510834 Hartree` for
H2O/STO-3G.

## Building and running

Requirements: CMake ≥ 3.22, a C++17 compiler, Python 3 with NumPy/SciPy/PySCF
for the validation and plotting scripts, and optionally a CUDA toolkit.

```bash
python3 -m venv .venv
.venv/bin/pip install numpy scipy pyscf matplotlib pytest
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

The build prints the detected tier and downgrades to the CPU backend when no
CUDA toolkit is found.  `results/environment.json` records the compiler, CPU,
GPU, nvcc version and tier.  CTest runs 8 executables in about 3 s and pytest
runs 9 checks (`results/test_summary.txt`); the same 8 CTest executables also
pass under a `-fsanitize=address,undefined` Debug build.

Python:

```python
from cuest import Cuest
lib = Cuest()
basis = lib.basis("data/molecules/h2o.json", "sto-3g")
S = lib.overlap(basis)          # (7, 7) float64, unit-normalized functions
E = lib.eri_tensor(basis)       # (7, 7, 7, 7)
```

Reproduce every measurement (environment, reference tables, build, CTest,
PySCF validation, RHF closed loop, error sweeps, screening, benchmark,
occupancy, `results/RESULTS.md`):

```bash
./scripts/run_all.sh
```

### Boys corner cases

3900 values over `T = 1e-16 … 1e3` and `n = 0…12` against SciPy: worst relative
error 4.94e-14 at `T = 8.06e-15`, `n = 10` (small-T Taylor branch).  The

branch taken by every value is recorded in `results/boys_corner_cases.csv`.
Figure: `results/figures/boys_corner_cases.png`.

### fp32 versus fp64 under conditioning stress

Near-degenerate exponents (ratio `1+δ`, δ down to 1e-10) and near-coincident
centres (separation down to 1e-10 bohr): the worst fp32-vs-fp64 scaled error is
1.18e-06, and the error changes by at most about 2× across ten decades of δ and
not measurably across ten decades of separation.  The Gaussian-product
formulation keeps the product centre and the Boys argument bounded, so there is
no cancellation amplification to measure.  All 580 per-class rows are in
`results/precision_error_growth.csv`; figure:
`results/figures/precision_error_growth.png`.

## Limitations and what's next

- Only s, p and d shells (l ≤ 2).  Higher angular momentum is rejected with
  `CUEST_NOT_SUPPORTED`.  The recurrences are written for arbitrary l, but the
  preallocated Hermite tables and the component loops are sized for l ≤ 2.
- No derivative integrals (nuclear gradients, Hessians) and no spherical
  harmonics; the basis is Cartesian and every component is unit-normalized.
- The CUDA backend was not compiled or run in this build (Tier C).  It shares
  the exact kernel headers and the host code is complete, but no GPU number is
  claimed.  The CI includes a CUDA compile-only job to keep the device path
  from rotting.
- The CUDA batch entry point returns `CUEST_NOT_SUPPORTED`; the CPU backend
  implements it.  The CUDA tensor path uses one thread per component quartet
  inside a per-quartet block, which is simple but not the fastest mapping.
- Rys is consistently within round-off of MD but, in this implementation, not
  faster: the on-the-fly root construction costs more than the Hermite
  recursion saves at l ≤ 2.  It is kept as an independent accuracy check, and
  the measured MD/Rys ratio is in the benchmark table above.
- The installed package resolves its basis data from `CUEST_DATA_DIR` or the
  compile-time source path; a fully relocatable data search is future work.
- Next: nuclear gradients, f shells, spherical transformation, a relocatable
  data directory, and a real GPU measurement at Tier A.
